# DevOps Task Dashboard

A React UI, Express API, PostgreSQL database, and Node.js polling worker. The worker claims pending tasks and marks them completed. This is a learning/demo implementation, not a production-grade durable job queue.

## Requirements
Docker with Docker Compose v2.

## Run
From the `application` directory:

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f worker
```

Open http://localhost:8080 and add a task. It should move from pending to processing to completed. The frontend uses Nginx to proxy `/api/` to the backend service, so no browser CORS configuration is needed.

## API

```bash
curl http://localhost:8080/api/tasks
curl -X POST http://localhost:8080/api/tasks -H 'Content-Type: application/json' -d '{"title":"Test background job"}'
```

Backend health endpoints (inside Compose network): `/health`, `/ready`.

## Stop

```bash
docker compose down
```

`docker compose down -v` also deletes local database data.

## EKS considerations
Use a managed PostgreSQL instance (e.g. RDS), Kubernetes Secret for DATABASE_URL, and separate Deployments/Services. Nginx's `backend` hostname assumes a Kubernetes Service named `backend` in the same namespace. Replace demo database credentials. Add migration tooling and recovery/retry behavior for interrupted jobs before production use. Commit dependency lockfiles generated by `npm install` before implementing reproducible CI builds.
